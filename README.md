# devops
1. Предметная область и краткое описание проекта
Проект: веб сайт интернет магазина с каталогом товаров, корзиной, оформлением заказа и простой админ панелью.
Цель: разработать учебное приложение с базовым функционалом электронной коммерции на монолитной архитектуре.
Основные функции (MVP):
•	Каталог и карточка товара: название, цена, фото, описание, наличие.
•	Фильтры/поиск по категориям и ключевым словам.
•	Корзина и оформление заказа: контактные данные, адрес, способ оплаты (заглушка).
•	Личный кабинет: регистрация/вход, просмотр заказов.
•	Админ панель: CRUD для товаров и категорий.
2. Выбор архитектуры
Архитектура: монолитная. Все подсистемы (frontend, backend, БД логика) разрабатываются и поставляются как единое приложение.
Почему для учебного проекта:
•	Простая сборка и деплой через Docker Compose.
•	Низкий порог входа: меньше сервисов и инфраструктуры.
•	Достаточно для небольшого интернет магазина с ограниченным трафиком.
Ограничения: масштабирование всего приложения целиком, слабая изоляция модулей по сравнению с микросервисами.
3. Основные части проекта
3.1 Общая схема
Пользователь (браузер)
        │
        ▼
  Vue 3 SPA (статические файлы через Nginx)
        │ запросы HTTP (REST)
        ▼
  Backend (Node.js 20 + Express) — бизнес логика и API
        │
        ▼
  PostgreSQL — хранение данных
3.2 Фронтенд (Vue 3)
•	Фреймворк: Vue 3, сборка через Vite.
•	Маршрутизация: Vue Router (главная, каталог, товар, корзина, заказ, профиль, админ).
•	UI: базовая верстка на Tailwind CSS или простом CSS.
•	Обмен с сервером: Axios, формат JSON.
3.3 Бэкенд (Node.js + Express)
•	REST API: товары, категории, корзина, заказ, пользователи.
•	Аутентификация: JWT (регистрация, вход, refresh по упрощенной схеме).
•	Логи: консоль, минимальная структура логов запросов.
3.4 База данных (PostgreSQL)
Ключевые таблицы:
•	users: id, email, password_hash, role, created_at
•	products: id, title, description, price, stock, category_id, images
•	categories: id, name
•	orders: id, user_id, status, total_amount, created_at
•	order_items: id, order_id, product_id, qty, unit_price
Пароли хранятся в виде хэша (bcrypt). Внешние ключи обеспечивают целостность данных.
4. Примерный pipeline разработки (GitHub)
1.	Исходный код хранится в репозитории GitHub.
2.	Ветвление: main (релизы), dev (интеграция), ms(моя ветка).
3.	Разработчик создает ветку feature, вносит изменения, делает коммиты с понятными сообщениями.
4.	Открывается Pull Request в ветку dev. Автоматически запускается CI (GitHub Actions): линтеры, тесты, сборка.
5.	Проходит код ревью. После одобрения PR мержится в dev.
6.	Готовим релиз: создаем релизный тег, мержим dev → main. Простейший прод деплой — обновление контейнеров на сервере.

7. Пример REST эндпоинтов
•	GET /api/products — список товаров с пагинацией и фильтрами
•	GET /api/products/:id — карточка товара
•	POST /api/auth/register, POST /api/auth/login — регистрация/вход
•	POST /api/orders — создание заказа (из корзины)
•	GET /api/orders/me — мои заказы (для авторизованного пользователя)
•	Админ: POST/PUT/DELETE /api/admin/products — управление товарами
8. Риски и ограничения
•	Монолит требует деплоя целого приложения при изменениях.
•	Ограниченное горизонтальное масштабирование.
•	Упрощенная оплата реализована в виде заглушки (без интеграции с платежными сервисами).
9. План работ (этапы)
1.	MVP: каталог, товар, корзина, заказ без оплаты, регистрация/вход.
2.	Админ панель: CRUD для товаров и категорий.
3.	Тесты, базовая аналитика логов.
4.	Полировка UI и доступности.
